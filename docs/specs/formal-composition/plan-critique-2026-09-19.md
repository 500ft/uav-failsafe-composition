# Critique of the 2026-09-19 week handoff, and the revised week plan

The handoff `NEXT-WEEK-PLAN-2026-09-19.txt` (written 2026-09-19, 935 lines, held outside this repository in the pre-rename checkout) is a good plan: it is evidence-first, it freezes contracts before code, it preserves invalid runs, and it names kill conditions. This document keeps its structure and fixes what the empirical work on 2026-09-16 showed to be wrong or missing.

Severity: **Critical** = would produce a wrong result or a false bug report · **Major** = wastes a week or hides a real finding · **Minor** = traceability and hygiene.

| # | Finding | Why it matters | Severity | Fix applied here |
|---|---|---|---|---|
| 1 | **The two offboard event classes are not separable over MAVLink.** The plan freezes "offboard proof-of-life loss" and "offboard setpoint-only loss" as two of six classes. PX4 documents that over MAVLink *any* supported setpoint message is itself the proof of life; only the ROS 2 path separates the keep-alive (`OffboardControlMode`) from the setpoint topics [B4]. | Two of six classes would collapse into one identical stimulus, and the validation matrix would silently be 5 classes wide while reporting 6. | **Critical** | Event classes are re-frozen as six *injectable* classes: offboard loss, datalink loss, RC loss, GPS/estimator-validity loss, battery, geofence. Setpoint-only loss is deferred with an explicit trigger (a uXRCE-DDS path) in the decisions document. |
| 2 | **U4's bound over-estimates.** The plan bounds time-to-terminal by "the sum of configured delays plus 2.0 s". PX4 holds a *single* shared delay counter initialised from `COM_FAIL_ACT_T` (`framework.h` L284-286, `framework.cpp` L48-51, L143-147), not one timer per hazard. | Summing per-hazard delays inflates the bound, so a real violation sits inside the tolerance and is never reported. A property that cannot fail is not a property. | **Critical** | `protocols/unsafe-composition-properties.json` bounds U4 by `hazard_detection_timer + COM_FAIL_ACT_T + expected_manoeuvre_time + 2.0`, with the correction recorded in the file. |
| 3 | **U1 would fire on legitimate behaviour.** The plan's U1 is "hazard active beyond its configured delay plus 1.0 s without an engaged action". PX4 legitimately engages nothing when an exception bit matches the active mode (`COM_RCL_EXCEPT`, `COM_DLL_EXCEPT`, `failsafe.cpp` L465-513), when the action is configured `None` (the vendor default for `NAV_DLL_ACT`), when the UX rules downgrade to Warn while already landing or in RTL (`framework.cpp` L617-644), or during user takeover. The Hold-first delay itself only exists when `COM_FAIL_ACT_T > 0.1 s` and the action is delayable. | Each of these would be reported as an unsafe composition. The headline artefact of this programme is a bug report to PX4; a false one costs the project its credibility with upstream. | **Critical** | Five shared exclusions X1-X5, each source-linked, are applied to the properties; U1's bound is conditional on delayability. |
| 4 | **The 60-case matrix cannot validate the composition part of the model.** 6 classes × 2 configurations × 5 seeds are all *single*-event runs, but U2 and U3 are defined over two or more simultaneous hazards. | The model would be validated on single events and then trusted on pairs, which is the exact inference the programme exists to avoid. | **Major** | A second tier is added: 4 ordered hazard pairs × 1 configuration × 3 seeds = 12 paired cases, run after the single-event tier. Until those pass, any checker prediction that depends on interaction is labelled a hypothesis. |
| 5 | **The agreement thresholds are finer than n = 60 can resolve.** 95% of 60 is 57 runs; 90% is 54. The difference between "proceed" and "owner decision" is one run, and the Wilson interval on 57/60 spans roughly 86-99%. | A threshold that the sample cannot resolve turns a judgement call into false precision. | **Major** | Decisions D7 restates the rule as counts (≤3 disagreements proceed, 4-6 owner decision, ≥7 kill) and requires a Wilson interval beside every agreement figure. |
| 6 | **Byte-identical raw logs will never hold.** W3.3 asks for raw-log hash comparison "where byte identity is expected". PX4 uLog embeds boot and wall-clock timestamps. | A guaranteed mismatch would be read as non-determinism and could stop the week for no reason. | **Major** | The reproducibility check compares normalised sequences and timestamps against a declared tolerance; byte identity is explicitly not expected, and the uLog hash is recorded for provenance only. |
| 7 | **Lockstep does not make injection deterministic.** PX4 lockstep ties simulation time to the module, but the stimulus arrives over UDP from a host process on a wall clock. The bring-up script written on 2026-09-16 schedules injections on host monotonic time, which is the same defect. | Injection jitter is then attributed to the autopilot and inflates the measured timing error. | **Major** | Injections are scheduled on **vehicle** time: the runner waits for a telemetry timestamp to cross the scheduled value before injecting, and records both the scheduled and the observed vehicle timestamps. |
| 8 | **The no-fault control is assumed easy; it is currently blocked.** Wednesday depends on a normal-operation run. On 2026-09-16 the vehicle refused to arm in SIH SITL ("Arming denied: Resolve system health failures first"); failure injection being enabled was ruled out as the cause. | Every downstream task depends on a trace that does not yet exist. A plan that discovers this on Wednesday loses three days. | **Major** | An apparatus bring-up task is inserted *before* the runner contract, with its own blocker path and a named next diagnostic (log `health_report` from boot, or query the running instance's pre-arm check list). |
| 9 | **The checker is a resource decision, not a probe.** UPPAAL/verifyta is absent on this machine and is not installable without accepting an academic licence. | Thursday's model work has no way to run. | **Major** | Raised to an owner decision (D8) with the three options stated: accept the licence, defer checking and deliver the model plus queries, or choose another timed-automata checker. No homemade reachability engine, per the handoff's own rule. |
| 10 | **The stated base commit is stale.** The handoff names `929cc8a` as "latest known main" from a checkout that was 19 commits behind; `929cc8a` is in fact the merge of PR #6, which you merged on 2026-09-16 after the audit PR. | A branch cut from the wrong base silently drops merged evidence. | **Minor** | This branch is cut from `929cc8a` and the fact is recorded with the PR #6 merge date in the evidence README. |
| 11 | **Proposed paths collide with existing conventions.** The handoff proposes `tools/sitl/`, `protocols/px4-study-a-matrix.json`, `protocols/authority-loss-trace.schema.json`. `tools/` in this repository holds the presentation checkers that CI runs, and the matrix and trace contracts were already built on 2026-09-16 under different names. | Two parallel identity systems is the failure the handoff itself warns about. | **Minor** | Deviations are recorded in decisions D10 with the reason for each; the handoff permits this. |
| 12 | **`SYS_FAILURE_EN` is never mentioned.** Every non-stream injection (GPS, battery, RC signal) requires it, and it is off by default [B3][B10]. | The first three event classes would silently do nothing. | **Minor** | It is a common parameter in every matrix row and is asserted in the runner's pre-injection check. |

## What the handoff gets right and this plan keeps

Evidence-state labelling on every artifact; raw and normalised traces stored separately; invalid runs preserved with reasons and excluded from denominators without deletion; a verified null treated as a result; the ban on post-hoc model-structure repair; one vehicle, one release, fixed seeds; no new model checker; the stratified analysis table; the three-PR split; and the final review checklist. The decision tree in F5.2 is adopted verbatim except for finding 5.
